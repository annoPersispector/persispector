## Warnings

- Outbound mail was redirected to 127.0.0.1:18206 (runtime property override, no source change) to honour the no-external-services policy; endpoints that send mail therefore return a generic 500 after their persistence work has committed. Persistence was confirmed by SQL trace and read-back, not by status code.
- Read-backs use SELECT statements through the application's own H2 web console (/h2) on the permitted port, authenticated as the seeded admin.
- Deployed schema adds constraints not in the analysis: UNIQUE(user_id) on password_reset_token and verification_token and UNIQUE(user_location_id) on new_location_token (from @OneToOne). C09 showed the password_reset_token one surfaces as an unhandled generic 500 on a second reset request for the same user.
- Run 1 (logs/run1, raw/run1) was a preliminary run with less web logging; the reported evidence comes from run 2.
